# Chrome Web Store submission — copy-paste cheat sheet

Everything the Chrome Web Store dev-console asks you to fill in for
the **Chess Coach — Review After Game** extension's first submission,
in the order the form presents it. Copy-paste straight from this file.

> Replace `<YOUR-PROD-HOST>` everywhere with your actual production
> Chess Coach hostname (e.g. `chess-coach.pages.dev` or your custom
> domain). Do this _once_ here, not in the dev console — it's easier
> to keep this file as the single source of truth for what was
> submitted than to remember which fields you customised in the
> browser.

---

## Before you click "New item"

Run the build, **with the production URL baked in**:

```bash
npm run extension:build -- --coach-origin=https://<YOUR-PROD-HOST>
```

Output: `dist-extension/chess-coach-0.1.0.zip`. That's the file you
upload in the **Package** tab.

Verify it once with `unzip -l dist-extension/chess-coach-0.1.0.zip`
— `manifest.json` and `icons/icon128.png` must be at the archive
root (not nested under a `chess-coach/` folder), or the dev console
rejects the upload.

### How to capture the screenshot

The reviewer wants to see the extension actually doing its thing.
Easiest path:

1. Open `chrome://extensions` and load `extension/` unpacked
   (after running `node scripts/build-extension-icons.mjs` to make sure
   `extension/icons/*.png` exists).
2. Open chess.com, finish any game (or rage-resign one) so the
   extension's prompt appears.
3. Resize the window to ~1280×800 (Chrome devtools → device toolbar
   → Responsive → set 1280 × 800).
4. Take a full-tab screenshot (devtools command palette →
   "Capture full size screenshot"; or your OS screenshot tool).

A second screenshot showing the **Options page** (with the URL
filled in and "Connected ✓" status visible) helps reviewers
confirm the privacy story.

## Privacy practices tab

This is the section that gets first submissions rejected most
often. The exact wording below has been written to match the
extension's actual behaviour, which is what the reviewer checks.

### Single purpose statement
```
Detect the end of a Chess.com game and offer a one-click deep link to import that game into the user's own Chess Coach analysis tool.
```

### Permission justifications

Click each permission and paste the matching block.

#### `storage`
```
Persists the user's Chess.com username, their Chess Coach app URL, and a boolean toggle for whether the after-game prompt should appear. No other data is stored.
```

#### `host_permissions: https://www.chess.com/*`
```
The content script runs on chess.com pages to detect when a game ends (via DOM observation of the post-game UI) and to read the game's URL so the deep link can carry it to Chess Coach. No data is sent off the user's machine — the deep link is a tab navigation in the user's own browser.
```

#### `optional_host_permissions: http://*/* and https://*/*`
```
Optional, requested only when the user clicks the "Test connection" button on the extension's options page to verify their Chess Coach URL is reachable. Granted per-host with the user's explicit consent via the standard chrome.permissions.request prompt; never granted up-front.
```

### "Are you using remote code?"
**No.** The extension ships only the JavaScript inside the zip.

### Privacy policy URL
```
https://<YOUR-PROD-HOST>/privacy
```

(That route is the `PrivacyPage` component at `src/features/legal/PrivacyPage.tsx`, served publicly outside the auth gate. Verify it loads before pasting.)

### Data usage disclosures

The form gives you a checkbox grid like *"Personally identifiable
information"*, *"Authentication information"*, *"Personal
communications"*, etc., and asks which ones the extension
**collects, uses, or transmits**. The honest answer for this
extension is **none of them** — it stores a username and a URL in
local sync storage and does not transmit anything. Tick **none**.

The two affirmative declarations the form requires:

- ☑ "I do not sell or transfer user data to third parties, apart
  from approved use cases."
- ☑ "I do not use or transfer user data for purposes that are
  unrelated to my item's single purpose."
- ☑ "I do not use or transfer user data to determine
  creditworthiness or for lending purposes."

## Submitting

Click **Submit for review** at the top right.

- **First review:** typically 1–3 business days. Sometimes same
  day, occasionally a week. Email notification when done.
- **Common rejection reasons** (and how to avoid them):
  - "Single purpose doesn't match what the extension does." Fix:
    re-read the single-purpose statement above and confirm it
    matches the screenshots and description.
  - "Privacy policy URL doesn't load." Fix: verify
    `https://<YOUR-PROD-HOST>/privacy` returns 200 and renders the
    PrivacyPage publicly. Hard-refresh in an incognito window.
  - "Description is keyword-stuffed." Fix: don't add SEO keywords
    to the description. The text above is intentionally plain.

If rejected, the email lists the exact reason. Fix it, click
**Re-submit**. Subsequent reviews are usually under 24 hours.

## After approval — releasing updates

For every release:

1. Bump `version` in `extension/manifest.json` (Chrome rejects
   re-uploads of an existing version).
2. `npm run extension:build -- --coach-origin=https://<YOUR-PROD-HOST>`
3. Dev console → your item → **Package** → **Upload new package**.
4. **Submit for review**.
5. Approval typically lands within an hour. Chrome auto-pushes
   the update to installed users within ~24h after that.

The `version` field follows Chrome's `x.y.z.w` numeric scheme
(each segment 0–65535). Semver works fine — `0.1.1`, `0.2.0`, etc.
